# 审核台管理员守则

> 2026-10-13 立。给**所有拿得到 `ADMIN_TOKEN` 的人**看 —— 不只站长。
> 这份文档只讲「怎么判、按什么顺序做」；接口与实现见 `docs/community-editing-plan.md`，
> 账号系统的细节见 `docs/accounts.md`。

## 0. 一句话

**你不是在「批准内容」，你是在替站长把关「这条能不能代表本站」。**
拿不准就**不通过**（驳回要写理由），宁可慢一天，也不要让一条错资料挂在页面上。

## 1. 你能做什么（权限边界）

| 能 | 不能 |
|---|---|
| 审核投稿：通过（攒着）/ 驳回（写理由） | 改投稿人写的原文（要改就让 TA 改，或采纳草稿时自己动手） |
| 点「写回仓库」把待写回的一批一次发布 | 直接 push 代码 / 改站点结构 |
| 采纳整篇草稿为原稿 | 删除已发布的资料（要删走 GitHub，留下记录） |
| 封禁来源、停用账号、重置口令、改名 | 看到投稿人的明文联系方式之外的个人信息（只有 IP 哈希） |
| 给账号挂「授权 UP 主」称号 | 发「授权 UP 主」给没在同意名单里的人（服务端会拒） |

**做任何一步都不需要问站长**，但**每一条都要能说出理由** —— 尤其驳回与封禁。

> 2026-10-14 起多了一条**可选**的登录方式：GitHub 登录（见 `docs/accounts.md`）。
> 它不改审核台的任何判定，只影响「仓库贡献者」称号：账号**自己用 GitHub 登录 / 绑定**
> 且登录名在仓库贡献者名单里时，称号自动挂上；名单外的人绑了 GitHub 也不会拿到称号
> （称号仍是对外承诺，人工挂 / 摘的入口照旧保留）。

## 2. 日常动线（一次 5 分钟）

1. 打开 `/admin/`，看顶部数字：`待审 N · 待写回 M · 已上线 X · 已驳回 Y`。
   - 上面那条工具条是**吸顶**的：标签页带计数；右边搜索框按 `/` 直接聚焦，
     输地图中文名也能搜（例如「米那斯」→ 自动变成这张图的过滤）；另有 `刷新`、
     `自动刷新`（30 秒一次，只在没勾选、没开对话框时静默刷新）、`清除密钥`（公用电脑上审完就走）。
   - 条数多时列表**分页**，底下「加载更多」接着看。搜索 / 筛选都由服务端做，
     找的是**整个队列**，不是当前这一屏。
2. **待审**：一屏一条，看「现值 vs 新值」。判据见第 3 节。
   - 卡片头：地图中文名 + slug（点 slug = 只看这张图的投稿）、字段、状态、编号、时间。
   - 正文很长时现值 / 新值各自先折到 8 行，点「展开全文」再看；整篇草稿显示字数 + 小节名。
   - 通过 → 进「待写回」（**还没发布**）；驳回 → 弹出对话框，可点快捷理由再补一句
     （投稿人凭编号能查到）。
   - 一次处理多条：勾「选中」→ 顶部「批量通过（攒着）」或「批量驳回」（同一个理由）。
3. **待写回**：攒到 5～10 条、或隔天点一次 **「写回仓库（一次提交）」**。
   点了会**先弹确认框**：把条数、涉及的地图、封面 / 图片集张数摆出来 ——
   这一步产生真实 commit 并触发一次重建，看清了再点「写回仓库」。
   一次提交 = 一次构建，别一条一条点（构建有额度，也污染提交历史）。
4. 写回后**抽查 1～2 个页面**（构建约 1~2 分钟）：确认改的内容真的出现了。
5. 有整篇草稿 → 点顶栏 **「整篇草稿」** 标签集中处理，见第 4 节，
   **通过 / 写回 / 采纳都各有确认框**（采纳是单独一步、单独一次提交）。

> 台子上的按钮都是**看得见、点得动**的：2026-10-13 之前投稿页与审核台的 `.btn`
> 没有任何基础样式（Tailwind preflight 把按钮清零了），显示效果接近纯文字；
> 现在审核台有自己的按钮 / 卡片 / 标签 / 对话框样式（`global.css` 里 `.admin-page` 一段）。

## 3. 逐条判据

### 3.1 一律通过（低风险）

- `sources` / `videoUrls` 补链接：**只看两点** —— 链接是不是真能打开、是不是对应这张图。
  视频只收 B 站（服务端已强制）。
- 标签：只加不减通常没问题；**整组替换**要看仔细，删掉标签会让「同类地图」推荐变化。
- 神器 / 道具一行行的更正：与服务器配置对得上就通过；**社区值与配置值不一致是正常的**（我们服改了），
  但要在备注里说清差别。
- 神器 / 道具的**删除**（动作列显示「删除」）：通过后那一行会**从表里消失**，表下只留一句
  「社区反馈本图没有这 N 件（谁说的）」。审这条时看两点：名字确实是本图没有的（不是打错字）、
  以及删掉之后表里还剩得下东西 —— 整张表被删空的话页面上就只剩那句说明了。

### 3.2 要核对来源（中风险）

- `difficulty`、`players`、`duration`、`stages`：**必须能在来源里找到依据**（工坊页、社区难度表、录像）。
  拿不准 → 驳回并写「请补一条来源」。
- `author` / `authorNote`：署名纠纷最敏感。**只认工坊署名或作者自述**；社区猜测一律驳回。
- 正文（背景故事 / 攻略 / 补充说明）：内容对不对是次要的，**先看是不是原创整理**。
  整段搬运别人的攻略 → 驳回（版权，见 `NOTICE`）。
- **社区整理（`section`，自定义小节）**：审核台会先显示「N 节小节：标题「A」、标题「B」…」与字数。
  这些节会以**投稿人自己起的标题**显示在条目末尾，所以审两件事：① 标题别和本站小节**意思重复**
  （撞名服务端已拦，但「关卡要点」这种和「关卡」重味的要靠人判断）；② 内容确实是原创整理、
  不是整段搬运。一张图累计最多 6 节（服务端拦），要改就让人用「修订这条」。

### 3.3 直接驳回

- 广告、联系方式、拉群、导流；侮辱与人身攻击；涉政涉黄涉暴；与地图无关的内容。
- 明显是机器刷的（同一 IP 短时间多条、内容雷同）→ 驳回 + **封禁此来源**。
- 想改的其实是**别人已经写好的正文**却说不出错在哪 → 驳回，让他投「整篇条目草稿」或补充说明。

### 3.4 驳回话术

三句话内说清：**哪里不行 + 怎么改就通过**。例：

> 「米那斯提力斯的难度改成『困难』需要有来源：这条是 UB 难度表还是你们服的实测？
> 补一条链接我就通过。」

## 4. 整篇草稿与「采纳为原稿」（大面积修改）

**这是唯一能改写人工原稿的入口**，所以规矩最严：

0. **去哪儿找草稿**：审核台顶栏的 **「整篇草稿」** 标签（2026-10-15 加）。它只看 `field=draft`
   的投稿，默认停在 **「待采纳」**＝已经写回仓库、页面上正挂着「社区整理版（未采纳）」的那几篇，
   每条都摆着「采纳为原稿」，不再跟难度 / 标签那些混在「已上线」里一条条翻。
   - 那一档里的小标签是**草稿自己的**计数：待采纳 / 待审 / 待写回 / 已驳回。
   - **采纳过的会从「待采纳」里走开**（服务端记 `submissions.adopted_at`）——
     不然采纳十几篇之后它又攒成一堆存货。条数写在状态条上（「已采纳 N 篇」），
     想看它们点右边的 **「翻看已采纳的」**（那种卡片上不再摆「采纳为原稿」，只留「再合并一次」）。
   - 老库 / 老草稿的 `adopted_at` 是空的，仍会留在「待采纳」里 —— 卡片上会写着
     「✅ 这篇已经采纳过了」，以社区文档里的记录为准（社区文档才是「采纳过没有」的最终依据）。
1. 草稿**必须登录**才能投（服务端强制），上限 2 万字，必须带 `## 小节`。
2. 流程是**两步**：
   - 第一步：像普通投稿一样**通过 + 写回** → 页面上出现「**社区整理版（未采纳）**」整块内容
     （虚线框 + 金色横幅，明确写着未经采纳）。
   - 第二步：在审核台点 **「采纳为原稿」** → 按小节合并进 `data/research/<slug>.json`：
     **写到的节替换、没写到的节保留、新节追加**，草稿里的导语会变成条目简介。
     **立刻单独提交一次**（不进攒批）。
3. 采纳前**必须做完这三件事**：
   - 通读一遍：事实有没有来源？有没有把别的社区叫法当成官方设定？
   - 看节标题：**别让 TA 用草稿把好的小节挤掉**（同名才会替换，所以注意「关卡流程」这类通用名）。
   - 确认版权：整篇草稿里不能有整段搬运的攻略或未授权的图片描述。

> ⚠️ **采纳会被拒的四种情况**（2026-10-14 加，都是为了防止把原稿写坏）：
> · 草稿里**没有 `## 小节标题`** → 直接报错。合并出空正文会让
>   `scripts/content/generate-map-entries.mjs` 的断言「sections 必须是非空数组」把整站构建打挂
>   （当天真的挂了一轮）。正确做法：**驳回**，请投稿人在编辑器里给每节写标题。
> · 合并结果为空（草稿的节跟现有原稿一节都对不上、又没有新节）→ 同样中止，仓库不动。
> · **同一条草稿已经采纳过了** → 409 拦下。采纳后投稿行仍是「已上线」，按钮还在，再点一次就是拿
>   同一份旧草稿再合并一遍 —— 会把你**采纳后手工修过的原稿**盖回去。审核台会再说一遍这条投稿的
>   编号与采纳时间，确认无误才点「仍然再合并一次」（服务端要 `force: true` 才放行）。若只是又想改
>   原稿，请直接改 `data/research/`，或让投稿人重投一版新草稿（新投稿行不受这条限制）。
> · **小节标题是「标题行」**（`## - ze_flower (花之声) -` 这种，标题里带 `-` 或直接写着地图短名）→
>   400 `placeholder-title`。它不是小节名：原稿里没有同名小节，采纳后页面上就会多出这么一个标题，
>   内容还常和「基本信息」重复。**采纳框里会替你把它改写成「基本信息」**（可以改成别的，例如
>   「关卡流程」；留空则按原样新增 —— 服务端照样会拒，页面不会变丑）。这类稿子多半是投稿人把
>   条目标题行贴进了编辑器：提醒他 `## ` 后面只写小节名（`## 基本信息`）即可。
4. 采纳后：草稿从页面消失，贡献者仍然留在「社区参与」名单里（`fields.draft = 已采纳 …`），
   提交信息写明「替换 N 节 / 新增 N 节 / 保留 N 节 + 整理人」。
5. **出问题怎么办**：`git revert` 那一次提交即可（原稿在 git 里，随时可回）。

## 5. 账号相关

| 动作 | 什么时候用 | 注意 |
|---|---|---|
| 停用（ban） | 确认的滥用者：刷号、发广告、恶意投稿 | 他手上的登录会立刻失效；投稿署名也不再挂到这个账号 |
| 恢复（unban） | 误判 / 本人来解释清楚了 | — |
| 解除锁定 | 连续 5 次口令错被锁 15 分钟，本人在群里求助 | 不解锁也行，等 15 分钟自己会好 |
| 重置口令 | **本站不收邮箱，这是唯一的人工找回入口** | 临时口令只显示一次，转告本人后请他立刻改 |
| 改昵称 | 昵称违规或本人要求 | 还没写回的投稿署名会一起改；已进仓库的要另开提交 |
| 挂 / 摘「授权 UP 主」 | UP 本人注册了账号（或站长确认身份） | 只能发同意名单里的人；**昵称一样也不自动发**（防冒名） |
| 挂 / 摘「仓库贡献者」 | 这个账号对应某位在 GitHub 仓库提交过资料的人 | 填 GitHub 用户名，**多个用逗号隔开**（一个人有两个号是常事：SiKi = trrrr-ai + MiKU，白叶 = xianoom + BaiYe）；服务端拿仓库贡献者名单核对，一个都对不上会拒绝；提交被 squash 过、名单里没有的号会在返回里点名，但仍会一并记下 |

两个称号都**只由人工发放**，代码里没有任何自动推断。徽章显示在账号页昵称下方与页头账号面板里：
「授权 UP 主」金色（点开去他的 B 站主页）、「仓库贡献者」青蓝色（点开去他的 GitHub 主页，
挂了多个号时指向仓库的贡献者页）。

**封禁前先看**：这个 IP 哈希下有几条投稿、有没有通过过。误伤一个认真投稿的人，代价比放过一条广告大。

## 6. 每天 5 分钟的自查

- 队列有没有积压超过 2 天？
- 「已驳回」里有没有写不出理由的？（写不出说明判据不清，该问站长）
- 上一次「写回仓库」之后，构建成功了吗（Cloudflare 构建页）？
- 有草稿挂着「未采纳」超过一周的 → 要么采纳、要么驳回，别让它一直挂着。

## 7. 明确不要做的

- ❌ 不要为了「凑活跃」通过一条你心里觉得不对的资料。
- ❌ 不要在采纳时顺手改草稿内容 —— 要么让作者改，要么自己另投一条（留痕）。
- ❌ 不要把 `ADMIN_TOKEN` 写进任何会进仓库的文件、聊天记录或截图。
- ❌ 不要删除历史（`log`、git 提交）—— 出了争议，记录就是唯一的凭据。
