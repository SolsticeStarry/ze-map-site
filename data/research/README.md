# data/research/ —— 地图资料「原稿」

**要给某张地图补充或修正资料？改这个目录里的 JSON，不要改 `src/content/maps/` 下的 `.mdx`。**

## 为什么

仓库里有两个长得很像的东西：

| | 文件 | 是什么 |
|---|---|---|
| ✅ **原稿（改这里）** | `data/research/<地图英文名>.json` | 网站从它生成条目内容 |
| ❌ 打印稿（别改） | `src/content/maps/<地图英文名>.mdx` | 由脚本**自动生成**，改了会被覆盖 |

`src/content/maps/*.mdx` 的第 23 行有 `generated by scripts/content/generate-map-entries.mjs` 这一行，就是「自动生成、别手改」的标记。只要有人跑一次 `npm run maps:generate`，写在那里的改动会被整段覆盖 —— 这不是理论，实际发生过。

「地图英文名」= 地图页标题下面那行小字 = 网址里 `/maps/` 后面那一段（例如 `ze_flowering`）。

## 怎么改（网页上就能做，不用装任何东西）

1. 在这个目录里找到 `<地图英文名>.json`，点进去
2. 点右上角的**铅笔图标 ✏️**
3. 改下面这几个字段：

| 字段 | 说明 |
|---|---|
| `"difficulty"` | 难度。**只能填这七个之一**：`入门` `简单` `普通` `困难` `火星` `入土` `未知` |
| `"summary"` | 介绍正文。一段一行，段落之间写 `\n\n`（这是换行符，不是真的按回车） |
| `"tags"` | 标签数组，例如 `["剧情", "双结局"]`。成对的中括号、每个标签用英文双引号包起来，标签之间用英文逗号 |
| `"videoUrls"` | 视频链接数组，写法同上 |
| `"sources"` | 资料来源链接。**有 `summary` 就必须至少给一条** |
| `"confidence"` | 资料可信度：`high` / `medium` / `low` |

4. 往页面下面拉，写一句「改了什么」，点绿色按钮 **Propose changes**
5. 下一页点 **Create pull request**

## 三个千万别碰

- ❌ **`"slug"`** —— 这是这张图的身份证（格式 `2001-<地图英文名>-<工坊ID>`），改了就和条目对不上了
- ❌ **`src/content/maps/` 下的 `.mdx`** —— 打印稿，改了白改
- ⚠️ **标签要照站内已有的写法**。比如是「传送门多」不是「传送多」，写岔了会凭空多出一个只有一张图的空标签页

## 如果这张图还没有 JSON 文件

说明还没人整理过它的资料（大量地图都是这种情况）。新建一个即可，最小可用长这样：

```json
{
  "slug": "2001-ze_xxx-1234567890",
  "title": "地图中文名",
  "difficulty": "普通",
  "summary": null,
  "tags": ["标签一", "标签二"],
  "confidence": "low"
}
```

- `slug` 从 `src/content/maps/<地图英文名>.mdx` 里的 `entitySlug:` 那一行抄
- `summary` 可以写 `null`（表示暂时没有正文介绍），但**这个字段不能删掉**
- 没有 `summary` 时不需要 `sources`

## 不想碰 GitHub？

用网站上的投稿表单：地图页右侧栏「✏️ 补充这张图的资料」。那个连 GitHub 账号都不用，填完进人工审核队列。

## 命令行（本机开发时）

```powershell
npm run maps:generate     # 从这些 JSON 重新生成 src/content/maps/*.mdx
npm run content:verify    # 校验这些 JSON（来源链接、难度枚举、可疑措辞等）
```
